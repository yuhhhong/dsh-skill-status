# dsh-skill-status

[![Awesome DSH Plugin](https://awesome-dsh-plugin.com/badge.svg)](https://awesome-dsh-plugin.com)

中文 | [English](<./README.en.md>)

DeepSeek Harness（DSH）的会话技能状态插件。在会话标题栏显示已确认加载的技能数量，点击「技能」打开右侧面板，查看完整正文是否仍在当前主助手上下文中，以及各次加载的正文版本与来源。支持按需机翻技能正文。

## 功能

- 合并当前技能目录与历史正式加载记录，支持按名称或说明筛选。
- 已加载的技能排在列表前面，同组内按名称排序。
- 识别 `/技能名` 和 `skill` 工具的正式加载记录，核对主正文是否完整保留。
- 查看历史正文版本、加载次数和加载时的资源指引；同一技能的多个版本只计数一次。
- 分别展示加载时的来源与当前目录来源；源文件后续修改不会覆盖历史正文。
- 随会话事件更新状态，安静期间每五秒复查目录和文件状态。
- 使用 Bing 或 Google 机翻当前查看的正文，支持目标语言设置、原文与译文切换、分块进度和只重试未完成块。

插件只查询当前主助手的技能状态，不提供加载、重载、卸载技能或修改会话内容的操作。

## 安装

方式1. 在 DSH 的 Web profile 中执行一条命令即可从 GitHub 安装：

```sh
dsh plugin --profile web add github:yuhhhong/dsh-skill-status
```

方式2. 在 dsh-market 中搜索 dsh-skill-status 并点击安装

方式3. 在 dsh 的插件页中，点击添加插件，填入项目仓库地址：<https://github.com/yuhhhong/dsh-skill-status>

安装后重启 DSH 并刷新页面，打开任意会话，点击标题栏右侧的「技能」入口即可展开面板。

如需卸载：

```sh
dsh plugin --profile web remove dsh-skill-status
```

当前插件版本为 `0.1.5`。支持的 DSH 版本范围为 `>=0.1.7-rc.2 <0.2.0-0 || >=0.2.0-rc.1 <0.3.0-0`；技能正文机翻需要其中的 `0.2.2-rc.2` 或以上版本。较早版本仍可查询技能状态，但不显示机翻入口。

## 技能正文机翻

先在 DSH 的「插件」中启用「思考过程机器翻译」，再展开技能条目，点击「上下文正文」或「历史正文」标题旁的「机翻」。正文会分块翻译，完成一块就显示一块；未完成或失败的位置保留原文，并显示对应提示。

翻译时可以点击「取消」，也可以通过「查看原文」和「查看译文」切换显示。取消或失败后，点击「重试未完成块」即可继续，已成功的块会复用。

在「插件」中打开本插件详情页，可设置：

- 翻译服务：Bing 或 Google，默认使用 Bing。
- 目标语言：默认跟随 DSH 界面语言，也可以指定语言代码，例如 `zh-CN`、`en` 或 `ja`。

两项设置点击「保存」后一起生效，并在重启后保留。折叠技能条目、切换正文版本或关闭面板会取消未完成的翻译请求。已成功的译文块仅缓存在宿主内存中，DSH 重启或本插件卸载后清空。

如果点击「机翻」时尚未启用翻译服务，会显示：

> 未检测到翻译服务。请前往「插件」启用「思考过程机器翻译」

启用后再次点击「机翻」即可重新检测。

机翻仅供阅读，不改变技能原文、来源或加载状态，也不会把译文写入会话上下文。代码、命令、路径和链接目标等片段保留原样。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 已加载 | 至少一个正式加载版本的完整主正文仍在当前上下文中 |
| 未检测到加载 | 可核实历史中没有正式入口成功加载的记录 |
| 完整正文不在上下文 | 已确认曾加载，但当前所有可核实版本的主正文都不完整或已移除 |
| 无法确认 | 历史、正文或当前上下文的证据不足 |

标题中的 `…` 表示尚未收到结果，`?` 表示查询失败或仍有无法确认的范围。`2 · ?` 表示已确认加载两个技能，但并非全部状态都已核实。

能归属到具体技能的问题直接显示在技能折叠行中，无需展开即可看到原因，例如完整原文缺失、只有间接调用日志、正文比对存在歧义或当前上下文暂时无法核实。加载状态与目录状态分开展示：`已加载 · 目录待确认` 仍表示正文已确认保留，不影响已加载计数；若仅其他版本无法核实，行内会注明“其他版本”。历史或目录不完整可能导致列表遗漏条目，面板会另行说明这些缺口。

普通文件读取不算正式加载证据。压缩摘要提到技能名字或曾经加载成功，都不能单独证明完整正文仍在上下文中。技能引用的资料是否被读取，不影响主正文的完整性判断。

加载记录中的资源指引不一定包含准确的源文件路径。只有当前技能目录提供明确路径时，插件才核查文件是否存在；该结果展示在「当前目录来源」下。

## 本地开发

安装依赖后可运行语法检查和测试。

```sh
pnpm run check
pnpm test
```

`pnpm test` 会先构建，再运行测试。`pnpm pack` 也会通过 `prepack` 自动构建。构建本项目不会自行更新正在运行的 DSH 页面。

`lib/` 的构建产物随仓库提交，请勿删除或忽略。pnpm 安装 git 来源的依赖时，会检查 `main` 指向的 `lib/index.js` 是否存在：不存在就判定该包需要执行构建脚本，从而要求 `allowBuilds` 授权；存在则跳过构建阶段。因此，保留 `lib/` 是从 GitHub 安装无需构建授权的前提。`prepack` 用于打包时重新构建。

改动 `src/` 后请运行 `pnpm run build` 并提交更新后的 `lib/`。测试会比对构建产物与当前源码，产物过期时会失败。

项目关闭自动补装 peer 依赖，DSH 宿主由目标运行环境提供，兼容版本范围见上方安装说明。

## 发布

推送 `v` 前缀标签会触发 GitHub Actions：核对标签与包版本、提取发布说明、检查已提交产物、运行语法检查与测试，全部通过后自动创建 GitHub Release，不附带压缩包。

发布前更新包版本、写入该版本的更新日志，并提交源码和 `lib/`。标签与包版本不一致，或更新日志缺少对应版本时，工作流会在发布前失败。

```sh
git tag -a v0.1.5 -m "发布 v0.1.5"
git push origin v0.1.5
```
